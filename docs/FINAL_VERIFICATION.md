# 요구사항 대조와 통합 검증

2026-09-25에 [원 과제](https://github.com/musinsatech/2026-musinsa-rookie/blob/main/PROBLEM.md)의 기능·동시성·초기 데이터·실행 요구사항을 현재 구현과 대조했다. 검증 결과와 남은 한계를 구분한다.

## 기능별 근거

| 요구 | 구현 및 검증 근거 |

추가 정책인 로그인·JWT 인증은 원 과제 기본 업무 API의 접근 조건으로 적용했다. 평가용 계정도 초기 데이터에서 생성하며 개발용 초기 비밀번호는 환경변수로 설정한다. 이메일·초기 비밀번호 설정의 실제 전송은 구현 범위에 포함하지 않는다.

## 실행 JAR 검증

기준 소스는 시간표 커밋 119e384이며 실행 검증 스크립트에 API smoke 검사를 추가했다. 운영 코드와 DB 스키마 변경은 없다. JAR SHA-256은 7C0D367A67A79017A5A2477057C2EEA833B0DC8F682C2E8CEEA31CCCFAC13411이다.

Windows 로컬 환경, Java 25.0.4.1, Spring Boot 4.1.1, PostgreSQL 18.6의 별도 임시 컨테이너를 사용했다. Gradle 전체 테스트와 기동 시간 측정을 동시에 실행하지 않았다. 대상은 기본값과 다른 2030년 1학기다.

~~~powershell
./scripts/verify-initial-data.ps1 -ApiSmoke -AcademicYear 2030 -Term 1
~~~

| 실행 | 프로세스 실행 요청부터 첫 /health 200 관측 | 초기 데이터 Runner | 결과 |
|---|---:|---:|---|
| 빈 DB 최초 생성 | 25.657초 | 6.914초 | 생성·검증 후 준비 완료 |
| 기존 데이터 재시작 | 18.449초 | 0.836초 | 초기 비밀번호 없이 검증·기존 데이터 보존 |
| 수업 시간 1건 누락 | 200 없음 | 준비 완료 없음 | 종료 코드 1, 기존 데이터 보존 |

두 정상 실행에서 준비 전 503과 준비 후 200을 관측했다. 최초 준비 직후 로그인 200, 학생·교수·강좌 목록 200, 신청 201, 시간표 200, 취소 204와 취소 후 빈 시간표를 확인했다. 초기 개수는 학과 10·교수 100·학생 10,000·과목 250·강좌 500·수업 시간 500·강의 담당 500·신청 0이었다. 재시작과 실패 전후 전체 행 해시가 같았다. 검증 프로세스·임시 컨테이너는 종료 시 정리한다.

별도 최초 기동 관측 1회는 25.210초였다(업무 API 검사는 포함하지 않은 실행). 이는 동일 조건의 통제된 반복 벤치마크가 아니다. 현재 환경의 관측값은 60초 이내지만 다른 장비·부하에서도 같은 시간을 보장하는 결과는 아니다. 위 시간은 /health 관측까지이며 이후 전체 API 호출 소요 시간을 합산한 값이 아니다.

## 동시성 및 전체 회귀 검증

마지막 한 자리에 대한 동시 요청을 기존 10명 외에 100명으로 확장했다. 테스트는 출발 장벽으로 HTTP 요청을 함께 시작하고 응답과 커밋 후 DB 신청 수를 검사한다. 실제 DB 잠금 획득은 순차화되며 100개 트랜잭션이 동시에 DB에서 실행된다는 뜻은 아니다. 10명·100명 사례 모두 통과했다. 100명에서는 201 성공 1건, 409 COURSE_FULL 99건, 최종 신청 수 1건을 확인했다.

전체 회귀 명령:

~~~text
./gradlew test bootJar --no-daemon
~~~

2026-09-25에 32개 테스트 클래스, 총 587개가 통과했다. 실패·오류·건너뜀 0, bootJar 성공이다. 기존 스키마·초기 데이터·인증·목록 및 신청·취소·시간표를 포함한다. 이 결과는 앞선 부분 테스트 합계를 재인용한 값이 아니라 현재 전체 실행의 XML 보고서를 집계한 값이다.

## 남은 범위

- HTTP 첫 기준값은 [부하 측정 기록](LOAD_BASELINE.md)에서 별도로 관리한다. 연결 풀·DB 잠금·자원 계측과 200명/30석 검증은 [부하 진단 기록](LOAD_DIAGNOSTICS.md)에 추가했다. 장시간·고정 유입률 부하와 순수 잠금 대기 시간의 백분위는 검증하지 않았다. 단발성 정합성 검증을 성능 보장으로 해석하지 않는다.
- 자동 재시도·토큰 재발급·로그아웃·실제 계정 초기 설정은 기존 후속 설계 항목이다.
- 선행 PR #8~#12는 main에 병합됐다. 사람 리뷰는 별도이며 이번 검토를 사람 승인으로 표시하지 않는다.

검토 범위와 측정에 반영한 의견은 [AI 자체 검토](reviews/final-verification-ai-review.md)에 기록했다.


## 후속 검증 및 제출 상태

2026-09-26 문서 점검에서 README의 구현 상태와 후속 범위를 갱신했다. API별 계약, DB·인증 환경변수 설정, 초기 데이터와 유효 ID 조회 경로는 README와 연결 문서에서 확인할 수 있다. 후속 진단 변경은 전체 590개 테스트 통과와 bootJar 성공 기록을 가지며, 앞선 587개 결과와 실행 대상을 구분한다. 이번 문서 점검에서 추가 부하나 전체 회귀를 재실행하지 않았다.

핵심 기능의 미구현 항목은 이번 대조에서 발견하지 못했다. 1분 이내 준비는 기록된 일반 실행에서 확인했으나 모든 환경에서 보장하지 않으며, 고부하 진단 실행 중 초과한 사례도 LOAD_DIAGNOSTICS.md에 남겼다. 토큰 재발급·로그아웃·실제 이메일 전송·자동 재시도는 기존 후속 설계 범위다. 제출 전 남은 절차는 이번 PR 검토·병합과 사람 리뷰이며, 성능 추가 측정은 현재 범위에서 종료한다.
