# 초기 데이터·준비 상태 AI 자체 리뷰

## 검토 범위

초기 데이터 생성과 저장, 기존 데이터 검증, V10 학과 코드, 대상 학기 설정, /health, 배치 처리와 재현 스크립트를 검토했다. 같은 작업을 지원한 AI의 자체 검토이며 독립적인 사람 리뷰를 받은 것으로 표현하지 않는다.

## 반영한 사항

| 항목 | 처리와 근거 |
| --- | --- |
| 초기화 완료 전 200 응답 | 데이터 완료 상태와 Spring Boot ReadinessState를 모두 검사한다. Runner 비활성화와 남은 기동 작업, 종료 시에는 503이다. |
| 생성·검증 학기 불일치 | EnrollmentTermProperties를 주입해 같은 설정을 사용한다. 범위·타입 오류는 기동 시 거절한다. |
| 배치 저장의 원자성 | 초기 생성 전체를 한 트랜잭션으로 저장하고 최종 검증도 포함한다. 앞·뒤 구간의 중복 PK와 검증 실패에서 전체 롤백을 테스트한다. |
| 재시작 시 데이터 손실 | 기존 데이터는 읽기 검증만 수행한다. 실제 JAR 재시작에서 전체 행 해시로 보존 여부를 확인한다. |
| 개발 DB에 의존하는 테스트 | ApplicationStartupTest도 Testcontainers를 사용해 개발 DB와 분리했다. |
| 성능 결과 과장 | 단일 표본과 측정 구간을 명시한다. /health 성공과 미구현 업무 API 완성을 구분한다. |

## 보류·제한

- V10은 기존 학과 행이 없는 DB를 전제로 한다. 실제 학과 코드가 없는 기존 데이터에 임의 코드를 부여하지 않으며 데이터가 있는 V1~V9 DB의 이행은 별도 작업이다.
- 초기화는 단일 애플리케이션 인스턴스 실행을 가정한다. 여러 인스턴스의 동시 초기화 조정은 아직 제공하지 않는다.
- /health는 기동 준비 상태이며 기동 후 DB 장애를 매 요청마다 검사하는 헬스체크가 아니다.
- 신청 API에서 정원·학점·시간 충돌을 보호할 잠금은 후속 구현이다. 초기 검증과 DB UNIQUE만으로 동시 신청 불변식이 보장된다고 주장하지 않는다.
- 배치 크기 50은 측정한 적용값이며 최적값 탐색 결과가 아니다. 모든 환경에서 1분 이내를 보장하지 않는다.

## 검증

2026-09-20 `gradlew.bat test bootJar --no-daemon`: 전체 204개 통과, 실패·오류·건너뜀 0. JDK 25, Spring Boot 4.1.1, PostgreSQL 18.6 Testcontainers를 사용했다. 실제 실행 JAR 검증 결과는 [초기 데이터 성능 기록](../INITIAL_DATA_PERFORMANCE.md)에 별도로 기록한다.

사람 리뷰는 아직 받지 않았다. 대상 학기 설정 변경 시 기존 데이터 처리, 준비 상태의 의미, V10 이행 전제를 중심으로 검토가 필요하다.
