# 로그인·JWT 인증 AI 검토

## 범위

로그인 입력 해석·검증, AuthService 연결, JWT 발급·검증, 공개·보호 경로, 오류 처리와 통합 테스트를 검토했다. 구현을 지원한 AI의 자체 검토와 별도 AI 에이전트의 추가 코드 검토를 수행했다. 추가 검토에서는 bcrypt 입력 경계 1건을 발견해 반영했다. 사람 리뷰는 아직 받지 않았다.

## 반영 사항

| 항목 | 반영 내용과 근거 |
|---|---|
| 숫자 문자열·소수의 자동 변환 | 로그인 전용 역직렬화기로 JSON 타입을 검사한다. 중복·지원하지 않는 필드와 후행 JSON도 400으로 거절한다. |
| 만료 경계 | 기본 60초 시계 오차 허용 대신 now < exp와 1800초 유효기간을 검사한다. 고정 시계로 만료 직전·동일 시각·이후를 HTTP 요청으로 검증한다. |
| 숫자 sub가 허용되는 문제 | 최초 전체 실행에서 서명된 숫자 sub가 200으로 수락되는 실패를 확인했다. Nimbus가 미리 문자열로 변환하므로 서명 검증 후 원래 JSON 타입을 추가 확인하도록 수정했다. |
| bcrypt의 72바이트 경계 | 초기 계정에서 허용하는 정확히 72바이트의 비밀번호에 접미사를 추가해도 bcrypt 대조가 통과할 수 있다. 서비스에서 UTF-8 72바이트 초과를 기존 401로 거절해 원문 일치를 보호한다. ASCII·한글 경계를 검증한다. |
| 비밀번호·토큰 노출 | DTO의 문자열 표현을 숨기고, 파싱·토큰 검증 예외의 원문을 응답하지 않는다. 로그인 성공 응답에 no-store를 적용한다. |
| 인증 실패와 업무 입력 순서 | 보안 필터에서 인증을 먼저 검사하며 실패 시 컨트롤러에 도달하지 않는다. 입력 오류는 학생 DB 조회 전에 거절한다. |
| 세션과 다른 토큰 전달 수단 | STATELESS, 요청 캐시·폼 로그인·Basic 비활성화, Authorization 헤더만 사용한다. CSRF 비활성화는 쿠키 인증을 사용하지 않는 현재 구조에 한정한다. |
| 공개 경로의 오래된 토큰 | 로그인·헬스체크에서는 기존 Authorization 값이 재로그인과 준비 확인을 막지 않는다. |
| 오류 디스패치 | 인증 이후의 404 등 HTTP 오류가 보안 필터에서 401로 바뀌지 않게 ERROR 디스패치를 허용한다. |
| 보호 경로 테스트의 범위 | 운영 업무 API를 임시 성공 응답으로 만들지 않고 테스트 전용 경로로 principal을 확인한다. 실제 업무의 본인 대상 처리·목록 응답은 후속 검증이다. |

## 보류·제한

- 재발급·로그아웃은 후속 설계로 남긴다. 서버 측 개별 토큰 무효화 저장소는 없다.
- 발급 후 학생 삭제를 고려하지 않는 기존 정책에 따라 토큰 요청마다 학생 DB를 조회하지 않는다.
- 없는 학번과 틀린 비밀번호의 오류 본문은 동일하다. 응답 시간 차이 완화·로그인 시도 제한은 구현·측정하지 않았으며 운영 보완 대상이다.
- 키 교체·유출 대응과 HTTPS 배포 구성은 후속 범위이다.
- 현재 사용자는 학생 단일 유형이며 별도 역할·권한은 도입하지 않는다.

## 검증 근거

[실제 실행 결과](../AUTH_API.md#검증)와 [추가 시나리오](../REQUIREMENTS.md)를 따른다. 첫 전체 실행은 300개 중 숫자 sub 사례 1개가 실패했으며 수정 후 전체 300개가 통과하고 bootJar 빌드가 성공했다. bcrypt 경계 보완 후 인증 102개(실제 HTTP·PostgreSQL 75개)를 다시 실행했고 모두 통과했으며 bootJar 빌드도 성공했다. 두 실행 모두 실패·오류·건너뜀은 0이다. 사람 리뷰는 아직 받지 않았다.
