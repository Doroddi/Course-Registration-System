# 스키마·JPA AI 자체 리뷰

검토일: 2026-09-19. 테스트 작성과 일부 SQL 보완에 참여한 AI의 자체 리뷰이다. 사람 리뷰는 아직 받지 않았으며 독립 검토로 표현하지 않는다.

## 검토 범위와 결론

Flyway V1~V9, 8개 엔티티·Repository, TeachingAssignmentId, application.yaml, Gradle 의존성 및 7개 Repository 테스트 클래스를 검토했다. 요구사항 D01·D11·D33~D34·D39·D76~D84와 대조했다. 현재 스키마 저장 범위에서 게시를 막는 코드 오류는 발견하지 못했다. 서비스·API의 동작이나 동시성 안전성을 보장하는 결론은 아니다.

130개 Repository 테스트의 XML 결과를 확인했다. 실패·오류·건너뜀은 모두 0이며 세부 건수는 [DB 검증 기록](../DB_SETUP.md)에 있다. 변경 없이 통과한 테스트를 리뷰를 위해 반복 실행하지 않았다.

## 반영한 검토 의견

| 의견 | 근거와 처리 |
|---|---|
| README·DB 문서·요구사항 머리말이 엔티티 미구현 상태를 나타냄 | 현재 구현과 달라 스키마·Repository 구현 및 실제 130개 검증 결과로 갱신 |
| ERD의 학기·요일·학년·학점 타입이 물리 타입과 다름 | D80 및 SQL의 SMALLINT 표기로 통일 |
| 전체 테스트와 Repository 테스트의 실행 조건이 다름 | ApplicationStartupTest의 개발 DB 의존성과 별도 Testcontainers 테스트 명령을 구분 |
| 최소 자식 개수와 동시성까지 스키마 테스트가 보장한다고 오해할 수 있음 | 후속 데이터 구성·서비스 검증으로 명시 |

## 확인한 구현

- 학번·과목 코드는 직접 부여하고 나머지 단일 PK는 IDENTITY로 생성한다. 수강신청 시퀀스는 CACHE 1이다.
- 강좌 코드는 연도·학기·코드 조합으로 유일하며 다른 학기·연도에 재사용할 수 있다.
- 강의 담당의 복합 PK와 EmbeddedId·MapsId가 대응한다. 교수·강좌를 삭제하는 cascade는 없다.
- 학생·교수·강좌의 학과, 강좌의 과목, 수업 시간·신청·강의 담당의 부모 참조는 필수이며 FK 삭제 제한을 둔다.
- 신청 삭제 후 재신청 시 새 ID를 발급하고 학생·강좌는 보존한다. 실제 취소 API는 아직 없다.
- V8이 PostgreSQL에서 허용하는 24:00을 차단해 LocalTime의 표현 범위와 맞춘다.
- JPA는 validate로 매핑을 확인하며 CHECK·인덱스는 SQL과 별도 테스트로 확인한다.

## 후속 검토와 보류 이유

| 항목 | 처리·이유 |
|---|---|
| 직접 부여한 ID의 save는 merge로 처리될 수 있음 | 학생·과목·강의 담당의 중복 INSERT는 JDBC로 검증. 생성 서비스의 중복 요청 응답은 해당 기능 구현 때 결정·검증 |
| 정원·학점·동일 과목·시간 충돌·신청 순서 동시성 | 스키마만으로 보장할 수 없음. 기존 잠금·트랜잭션 설계를 유지하고 서비스 단계에서 검증 |
| 수업 시간·담당 교수 최소 1개 | 현재 FK는 부모 존재만 보장. 초기 데이터 및 강좌 구성 검증에서 처리 |
| 시간 정밀도 | DB가 저장한 값의 분 단위 조건을 테스트. JDBC·DB의 정밀도 변환 전 원본 입력 검증까지 포함한 결과는 아니며 API 단계에서 별도 확인 |
| 전체 테스트의 개발 DB 의존성 | 실행 방법에 명시. 기동 테스트까지 격리하는 개선은 후속 작업이며 현재 130개 성공에 포함하지 않음 |
| 컨테이너 설정 중복·테스트 기동 시간 | 현재 테스트는 각 클래스의 컨테이너를 분리함. 공통 설정 추출은 선택적 개선이며 성능 향상을 측정한 것은 아님 |
| 소문자 패키지명·미사용 import·명시 Column 표기 | 기능 오류는 아님. 작성자 코드 스타일 정리는 별도 합의 후 진행 |
| OSIV·비밀번호 해시 접근·DTO | OSIV 비활성화는 기존 제안 상태 유지. 실제 비밀번호 해시와 응답 제외는 인증/API 단계에서 검증 |
