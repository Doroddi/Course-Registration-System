# 첫 설계 PR 초안

상태: 설계 검토용 PR 본문 초안

제안 제목: `chore: 프로젝트 초기 구성 및 수강신청 설계 문서 추가`

## 해결할 문제

수강신청 구현에 필요한 정책과 데이터 관계를 정의한다. 현재 신청의 저장 방식, 과목과 분반의 구분, 대상 학기 및 공동 강의 모델을 검토할 수 있도록 요구사항과 논리 모델을 정리했다.

## 변경 및 근거

- 기존 원격 초기 커밋을 기반으로 Java·Gradle 골격과 설계 문서를 별도 커밋으로 구성했다. 개인 IDE 설정은 제외했다.

- [요구사항](../REQUIREMENTS.md)에 불변식, 확정 정책, 미정 사항, 수용 테스트 초안을 구분했다.
- [ERD](../DATA_MODEL.md)에 현재 신청 관계와 교수 담당 관계, 개설 강좌별 수업 시간을 표현했다.
- 취소 데이터 보관 요구가 없어 상태 컬럼을 두지 않고 취소 시 신청 행을 삭제한다.
- 연도·학기별 강좌코드 재사용을 위해 개설 강좌에는 별도 식별자를 둔다.
- README, 협업 지침, PR 템플릿과 설계 관련 프롬프트 발췌를 추가했다.

## 검증

문서 8개의 내부 링크와 Git diff 공백 오류를 점검했다. Windows / Temurin JDK 21.0.11에서 `./gradlew.bat test` 실행이 성공했다. Java 컴파일은 완료됐으며 테스트 소스가 없어 `test`는 `NO-SOURCE`였다. API 동작 및 동시성 테스트 통과를 의미하지 않는다. Mermaid ERD의 렌더링 확인은 남아 있다.

## 리뷰 요청

1. ERD가 요구사항을 빠짐없이 표현하는가? 초안 필드·키 제안이 확정 정책처럼 보이지 않는가?
2. 동일 과목의 다른 분반 중복 제한이 동일 강좌 중복 제한과 구분돼 있는가?
3. 취소·재신청·대상 학기의 의미 및 미정 범위가 명확한가?
4. 동시성 테스트에 동일 학생의 학점·과목·시간 충돌이 포함되어 있는가?

## AI 활용 및 리뷰 상태

설계 작성자가 정책과 관계를 결정하고 AI가 반례 검토 및 문서 초안을 지원했다. [설계 관련 프롬프트 발췌](../../prompts/0001-design-conversation.md)에 관련 입력을 기록했다. [AI 자체 리뷰와 반영 결과](initial-design-ai-review.md)를 기록했다. 사람 리뷰는 후속 단계이다.
