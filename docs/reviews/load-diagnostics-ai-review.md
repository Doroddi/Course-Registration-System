# 부하 진단 AI 자체 검토

2026-09-26, main 49de8e7 기준 진단 변경을 검토했다. 사람 리뷰와 구분한다.

## 검토 범위와 판단

- 정원 30명에 200명 단발 신청: 통합 테스트와 k6에서 성공 30·COURSE_FULL 170, DB 신청 및 고유 학생 30을 검사한다. 반복 신청·취소 부하와 구분한다.
- 진단 지표: 기본 실행에서는 비활성화하며 진단 프로필에서만 루프백 별도 포트로 노출한다. JWT 인증을 적용하고 업무 포트 및 env 엔드포인트 비노출을 검증했다. 운영 관측 시스템의 별도 권한 모델을 구현한 것으로 해석하지 않는다.
- 데이터 보호: 측정 스크립트는 자신이 만든 임시 DB 및 경로를 검사한다. 임시 토큰 파일과 프로세스·컨테이너를 종료 시 정리하며 실제 개발 DB를 부하 대상으로 사용하지 않는다.
- 측정 해석: 연결 확보 평균과 신청 성공 p95의 모집단을 구분하고, DB 샘플의 쿼리 경과 시간을 순수 잠금 대기로 취급하지 않는다. CPU 포화와 계측 비용 때문에 최대 처리량이나 설정 개선을 주장하지 않는다.
- 공개 근거: 집계 JSON에 호스트 프로세스 이름·PID와 인증 토큰을 포함하지 않는다. DB 잠금 분석의 PostgreSQL PID는 차단 관계를 표현하는 측정값이다.

게시를 막을 기능 오류는 이번 검토에서 발견하지 못했다. README와 요구사항·최종 검증 문서의 오래된 후속 상태는 현재 구현 근거에 맞춰 수정했다.

## 검증 근거

기존 전체 회귀 기록은 33개 클래스·590개 테스트, 실패·오류·건너뜀 0과 bootJar 성공이다. 이번 검토에서 소스·빌드 설정의 해시가 그 검증 대상과 동일함을 확인했다. 새로운 회귀 실행으로 표기하지 않는다. 측정 실행과 정합성 결과는 [부하 진단 기록](../LOAD_DIAGNOSTICS.md) 및 연결된 JSON을 따른다.

## 보류 범위

추가 부하 측정과 풀·잠금 튜닝은 현재 범위에서 종료한다. 장시간 부하, 독립된 부하 생성 환경, 순수 잠금 대기 백분위와 성능 목표는 미검증이다. 별도 성능 요구가 생기면 환경과 합격 기준부터 정한다. 사람 리뷰와 PR 병합은 아직 별도 절차다.
