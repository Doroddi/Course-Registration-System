# 목록 조회 AI 자체 검토

검토일: 2026-09-24. 대상: 학생·교수·강좌 목록 API와 공통 입력 검증·페이지 응답. 구현을 지원한 AI의 자체 검토이며 독립적인 사람 리뷰와 구분한다. 사람 리뷰는 아직 받지 않았다.

## 검토 결과

PR 등록 전에 수정해야 할 기능 오류는 발견하지 못했다. 다음 항목을 확정 정책·코드·기존 테스트 근거와 대조했다.

| 항목 | 확인 내용 |
|---|---|
| 입력·인증 | 원시 MultiValueMap으로 중복을 유지하고 미지원 이름·필드·offset 순서로 검사한다. 인증과 입력 오류는 업무 DB 조회보다 앞선다. |
| 학생·교수 | 목록·count에 동일 필터를 적용한다. 현재 소속 학과를 사용하고 고유 식별자로 정렬한다. 학생 비밀번호 해시는 조회하지 않는다. |
| 강좌 페이지 | 서버 대상 학기·강좌 소속 학과로 필터링한다. numeric 코드와 ID 보조 정렬로 30자리 및 같은 숫자값을 처리한다. 다건 관계는 페이지 확정 후 별도 일괄 조회한다. |
| 집계·응답 | 수업 시간·교수 때문에 강좌·신청 인원이 중복 집계되지 않는다. 신청 집계에 없는 강좌는 0명이며 빈 페이지는 상세 조회를 생략한다. 원래 페이지 순서와 메타데이터를 유지한다. |
| 트랜잭션 | 서비스에서 읽기 전용 READ COMMITTED를 사용한다. 동일 응답의 여러 SQL에 단일 스냅샷을 보장한다고 설명하지 않는다. |

## 근거와 반영 판단

- 2026-09-23 목록·인증 테스트 284개 통과(실패·오류·건너뜀 0), bootJar 성공 기록을 확인했다. 공통 68개, 학생·교수 40개, 강좌 19개, 인증·JWT 설정 157개이다.
- 2026-09-24 현재 목록 운영·테스트 소스가 검증 당시 파일과 동일함을 해시로 확인했다. 기준 브랜치도 기존 검증 기반인 2153dca와 같아 테스트를 반복 실행하지 않았다.
- [학생·교수와 공통 검증](../LIST_QUERY_COMMON.md), [강좌 검증](../API.md#실행-결과와-한계)에 실제 실행 범위와 한계를 구분했다.
- 숫자 정렬의 표현식 인덱스 추가는 보류한다. 쿼리 횟수 확인만으로 인덱스 필요성이나 응답 성능을 단정할 수 없으므로 부하·실행 계획 측정 후 판단한다.
- READ COMMITTED에서 SQL별 시점이 달라질 수 있는 동작은 D92·D93으로 채택된 범위이다. 수강신청 성공 여부와 정원 보호는 후속 신청 트랜잭션에서 검증한다.

이번 검토는 전체 프로젝트 테스트 재실행·독립 AI 리뷰·사람 리뷰·부하 테스트를 수행했다는 의미가 아니다.
