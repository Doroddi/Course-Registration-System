# 초기 데이터 결정 정리

## 1. 초기 데이터 생성

> 요구사항에 맞춰 초기 데이터를 최초 생성하겠습니다. 재시작할 때는 기존 데이터를 보존하고 개수와 정합성을 확인하는 방향으로 진행하겠습니다.

## 2. 학과 코드와 학번 구성

> 학과 코드를 별도 필드로 두고 10~99번 사이의 코드를 부여하겠습니다. 학번은 2026 + 10(학과 코드) + 255(학생 번호)처럼 생성하겠습니다. 학번 끝 3자리의 학생 인덱스는 100~499, 연도는 2020~2026년 사이로 생성하겠습니다. 전과하더라도 학번은 변하지 않고, 현재 소속 학과는 department_id로 조회하겠습니다.

## 3. 불완전한 초기 데이터

> 초기 데이터가 일부만 있거나 정합성이 깨져 있으면 자동으로 채우거나 삭제하지 않고 기동을 실패시키겠습니다. 정상 데이터는 보존하고, 빈 DB에서만 초기 데이터를 생성하겠습니다.

## 4. 학생 분포와 초기 비밀번호

> 제안한 대로 학생 10,000명은 연도·학과별로 가능한 한 균등하게 배분하고, 학년은 학번 연도와 독립적으로 1~4학년에 균등 배분하겠습니다. 개발용 초기 비밀번호는 환경변수로 받아 해시하여 저장하겠습니다.

## 5. 초기 강좌 구성

> 제안한 강좌 생성 기본안에서 학점은 1~3학점으로, 담당 교수는 현재 강좌당 한 명으로 하겠습니다. 나머지는 2026년 2학기, 학과별 25과목과 과목당 2분반으로 구성하고 초기 수강신청은 없는 방식으로 진행하겠습니다.

## 6. 최초 데이터 저장 방식

> 최초 생성 코드에서는 이미 비어 있는 DB에 새 데이터를 넣는 것이니 존재 여부를 다시 조회할 필요는 없다고 생각합니다. 제안한 대로 학생·과목·강의 담당은 persist를 사용하는 방식으로 수정하겠습니다.

## 7. 초기 데이터 배치 저장

> 제안한 개선 항목 중 대량 INSERT의 배치 처리부터 적용해보겠습니다.

## 8. 대상 학기와 준비 상태

> 제안한 대로 대상 학기를 설정으로 통합하고, 초기 데이터 생성·검증이 끝나기 전에는 준비 완료로 응답하지 않도록 하겠습니다.
