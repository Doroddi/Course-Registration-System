# 부하 검증 방향

## 1. 성능 기준값 측정

> 제안한 대로 성능 합격선을 먼저 정하지 않고 기준값부터 측정하겠습니다. 현재 잠금 방식과 3초 대기 정책을 유지하고, 한 강좌 집중·여러 강좌 분산·조회 혼합을 동시 사용자 10·50·100명으로 비교하겠습니다. 처리량과 p95/p99 응답시간, 성공·409·503 비율을 구분해서 보고 결과를 본 뒤 성능 목표를 정하겠습니다.

## 2. 정원 경쟁과 지연 원인 확인

> 200명이 한 강좌에 신청했을 때 정원에 맞게 정확히 30명만 신청되는지 확인하겠습니다. 이후 제안한 연결 풀 대기, DB 잠금 대기, 쿼리 실행과 자원 사용 계측을 진행하겠습니다.

## 3. 부하 검증 마무리

> 추가 성능 측정은 여기서 마무리하고, 지금까지의 측정 코드와 기록을 검토해서 PR로 정리하겠습니다. 남은 요구사항과 제출 문서도 함께 점검하겠습니다.
